# 首版验证协议

真实 HCU 资源由用户后续提供。本文件不构成旧节点、旧凭据或整机独占授权。

## 真实验证前置

- 确认节点、单张物理卡、独占时间窗、服务端口、镜像摘要和本地 Qwen3-4B BF16 权重。
- 默认 SGLang 海光版，固定实际 commit，TP1；不替换或升级现有驱动/DTK。
- 在独立 Python 3.11 客户端环境执行；最好独立 CPU 机器，或明确限制 CPU/内存并避免与服务抢核。
- exporter 由节点负责人提供，仅只读抓取。建议 low 成本档，实际指标定义须与固定参考对照。
- PCI BDF 与 node 标签必须映射到服务使用的物理卡，不能凭容器内编号猜测。

## 矩阵

`python scripts/validation_matrix.py --config PRIVATE_CONFIG --output NEW_DIRECTORY` 仅生成配置，不运行。

按 smoke → fixed-c1/c4/c8 → poisson-r1/r2/r4 → 关闭遥测对照 → 增加客户端 CPU 对照顺序串行执行。
正式点各 128 请求、3 轮，固定点预热 16；Poisson 输入 512±128，其他输入目标 128，输出目标均为 128。
默认每轮 600 秒故障上限。首次 OOM、持续错误、资源冲突或超时停止剩余矩阵；不自动重启任何外部服务。
目标长度不等于实际长度；chat 模板会增加输入 token，必须在报告中核对实际值。

固定场景与 EvalScope 的独立环境交叉检查，同一模型、tokenizer、流式、输出约束和缓存策略。
记录 warmup、prefix cache、thinking 和并行参数。不能只对齐命令参数而忽略最终请求差异。

## 判定

- 请求计数、实际长度和有效流式事件可以核对；不把 HTTP 200 当作任务完全成功。
- 四项核心遥测有明确设备身份和单位；没有源采样时间戳时只报告观测，不能证明新鲜度。
- exporter 参考实现的部分底层调用可能在错误后输出零，适配层无法单凭数字检测；必须检查 exporter 健康及日志。
- 跨工具差异、客户端资源和遥测开销变化超出重复实验波动时先排查，不发布“性能可信”结论。
- 非流式 TTFT/ITL 未测量，不能补零；推理模型 TTFT 与 TTFO 不混比。
- vLLM、其他型号、虚拟卡、跨节点、精度和生产容量未实测，不继承本次结论。

## 遥测来源

exporter 固定参考 `30cfbc1031957737731725ceddb663bc508d7c96`；其依赖 hcu-dcgm v3.0.2。
`hcu_power_usage` 对应 Power 内部微瓦/1000000，即 W；温度内部毫摄氏度/1000，即 C；
`hcu_usedmemory_bytes` 为 bytes；`hcu_utilizationrate` 为瞬时 CU 利用率百分比，不等于 1 秒窗口指标。
代码不再重复换算这些已经标准化的数值。指标重命名或其他版本必须先更新映射测试。
