# 同时测推理性能与 HCU 功耗：并发 8 开关对照

2026-11-18 实测。在一张 BW1100 上运行 SGLang 0.5.18、Qwen3-4B BF16、TP1，开启轻量遥测后，本次没有观察到一致的吞吐损失；平均首 token 延迟比关闭时高 0.90 ms。三对实验不能证明开销为零，也不构成自动性能放行标准。

## 使用方式

仅测推理延迟和吞吐不需要 exporter。需要硬件数据时，先在推理节点起 hcu-exporter，并确保客户端可访问其 /metrics。一个节点级实例可以覆盖多张卡和多轮实验，不必每轮安装；临时启动或事先常驻都可以。aiperf-hcu 不自动部署 exporter。

在配置中开启 telemetry.enabled，填写 telemetry.url 和目标卡的 node、pcieBus_number。先用 doctor 检查，再执行一次 run：AIPerf 发送请求和记录响应时间，同时旁路采集器抓取指标。report.md 将两类数据放在同一份报告中，summary.json 保存结构化统计；run-001/telemetry.jsonl 保留每次读取的设备、采集时刻、单位与数值。无需为采集功耗重跑同一负载。

## 实验与结果

使用同一模型进程、镜像、tokenizer、服务端 usage 计数及随机种子。每轮 16 次预热、128 个正式请求，正式请求的峰值在途数均为 8；6 轮合计 768 个正式请求、96 次预热。六份正式请求计划的内容及排列一致，每条实际输入 136 token、输出 128 token。顺序为关闭/开启、开启/关闭、关闭/开启。客户端固定 4 个 CPU，服务端固定 8 个；共享节点未取得整机 CPU 独占。显存守护持续启用，两组均承担相同的守护开销。

关闭：客户端不抓取，专用 exporter 和转发服务均停止。开启：非特权隔离进程运行官方 exporter v3.0.2，整机 8 张卡仅采四项；exporter 每 5 秒更新一次，适配器每 1 秒抓取，只保留目标物理卡。下表每格为三轮各自均值再取平均。

| 指标 | 关闭 | 开启 | 开启减关闭 |
|---|---:|---:|---:|
| 输出吞吐（token/s） | 212.0680 | 212.0767 | +0.0087（+0.004%） |
| 首 token 延迟 TTFT（ms） | 206.8353 | 207.7378 | +0.9025（+0.44%） |
| token 间延迟 ITL（ms） | 36.3436 | 36.3363 | −0.0073 |
| 端到端请求延迟（ms） | 4822.4755 | 4822.4432 | −0.0323 |

| 配对 | 执行顺序 | 吞吐差（开−关，token/s） | TTFT 差（开−关，ms） |
|---|---|---:|---:|
| 1 | 关、开 | −0.192 | −0.032 |
| 2 | 开、关 | +0.681 | +1.816 |
| 3 | 关、开 | −0.463 | +0.923 |

吞吐变化方向不固定，绝对差小于关闭组三轮均值跨度（1.16 token/s）。TTFT 两对上升、一对近乎不变，不能据此断言是遥测导致，也不能证明毫秒级回归可忽略。TTFT 的单轮 p99 在关闭组为 213.50–213.91 ms，开启组为 213.85–214.65 ms；不是合并所有请求的 p99。

每个开启组每项指标读取 93 次，四项合计 1,116 条观测，无缺失或采集失败；关闭组三轮没有遥测记录。温度 33–37°C，瞬时 CU 利用率 0–100%，已用显存 13,360,918,528 bytes。功耗范围是记录到的样本范围，不是硬件的瞬时极值；统计区间包含客户端启动、预热和收尾。源样本无时间戳，连续抓取可读到同一个值，不能将这些值当成 1,116 个独立硬件采样，更不能据此计算单条请求的精确能耗。工具保留 freshness=unknown。

所有本轮模型、客户端及 exporter 已停止；服务和遥测端口均释放。测量仅适用于上述模型、设备、并发、轻量指标集及采集周期，不推广到高成本全量采集或多卡推理。早前的跨工具 TTFT 差异仍独立待核对。
